# Working note — Compile-only CI sweep of the sample/game/tutorial corpus

Branch: `devex/corpus-compile-sweep`
Type: Test coverage / DevEx

## Goal (restated)

INTENT value #1 is drop-in source compatibility: "compile their old game on day
one... Always." The repo ships ~350 legacy `.bb` programs under `samples/`,
`tutorials/`, and `games/` (and `publish.*` copies them into releases), yet CI
compiles exactly zero of them — only the 17 modern-feature files in `tests/`. A
parser/sema change can silently break a whole class of legacy syntax and CI stays
green. Two independent recon agents converged on this gap and measured ~32/352
files already failing to compile.

Build a compile-only sweep that runs `blitzcc -c +q` over the whole corpus, gate
it in CI against a checked-in baseline allowlist, and make the gate **ratchet**:
the currently-broken files are recorded with reasons, and CI fails only when a
*new* file stops compiling. This turns "always compiles" from aspiration into an
enforced invariant, and quantifies the legacy-compat erosion the loop has twice
deferred fixing.

## Approach (in order)

1. **`scripts/sweep_corpus.sh`** — portable bash (matches `test.sh`/`test_*.sh`):
   - Detect `bin/blitzcc` (Unix) or `bin/blitzcc.exe` (Windows).
   - Walk `samples/ tutorials/ games/` for `*.bb` (NUL-delimited; paths have spaces).
   - Compile each from **its own directory** (`cd dir; blitzcc -c +q basename`) so
     relative `Include` paths resolve the way they do for a real build.
   - Classify PASS / FAIL; capture the first diagnostic line of each failure.
   - Read `scripts/corpus_compile_allowlist.txt` (repo-relative paths, forward
     slashes, `#` comments). A FAIL listed there is "known" (does not fail the
     gate); a FAIL not listed is "NEW" → exit 1. An allowlisted path that now
     passes / no longer exists is a non-fatal "stale" warning.
   - Print a summary (total / pass / known-fail / new-fail) and the NEW-fail list.
   - `--update-allowlist` mode rewrites the allowlist from the current failures
     (used once to establish the baseline; not used by CI).
2. **`scripts/corpus_compile_allowlist.txt`** — the baseline, generated by running
   the sweep once, then hand-annotated by failure class:
   - keyword collision (legacy identifier vs new reserved word: `test`, `release`, …)
   - disabled/unregistered builtin (`SoundPan`, `PlayMusic`, `StartNetGame`, …)
   - include fragment / not a standalone entry point
   - external-lib / userlib dependency
3. **Wire into CI** (`.github/workflows/ci.yml`): add a sweep step to the Windows
   `build-and-test` job (after `test.bat`, `shell: bash`). Shipped Windows-only:
   the allowlist baseline reflects the Windows runtime's registered command set
   (the stable target). The macOS alpha job is intentionally NOT gated until a
   baseline is regenerated against its runtime metadata (its stub may register a
   different builtin set, which would surface as spurious new-fails).

## Acceptance criteria (Artifact B = the sweep + a deliberate-break proof)

- The sweep compiles every `.bb` under `samples/ tutorials/ games/` with `-c +q`,
  each from its own directory, and exits 0 on `develop` today (all current
  failures are allowlisted with a reason).
- A file that fails AND is not in the allowlist makes the sweep exit non-zero and
  names the file — proven by temporarily adding a throwaway sample that uses a
  reserved word as an identifier and watching the sweep go red, then removing it.
- An allowlisted file that now compiles produces a non-fatal stale warning (does
  not break CI).
- CI runs the sweep on the Windows job; existing `test.bat` / macOS smoke unaffected.

## Trade-offs / rejected

- **Not fixing the failures.** The keyword collisions (the deferred legacy-compat
  regression) and disabled builtins are recorded, not repaired — each is its own
  follow-up. The sweep's job is to stop the bleeding (ratchet) and quantify it.
- **Rejected: runtime subsystem tests (recon agent 2).** Audio/graphics/socket
  runtime tests need headless harnesses and are explicitly multi-iteration; lower
  single-iteration confidence. Deferred.
- **Compile-only, headless.** `-c` stops after assemble and never opens DirectX
  (`main.cpp` gates execution behind `!compileonly`), so the sweep is CI-safe.
- **Serial vs parallel.** Start serial for deterministic output and reliability
  (a flaky safety net is worse than a slow one); parallelize with `xargs -P` only
  if wall-time proves excessive.

## Deferred follow-ups

- Repair the allowlisted failures, class by class: legacy-identifier keyword
  collisions (the HIGH-priority contextual-keyword fix already tracked), and the
  disabled builtins (`SoundPan`/`PlayMusic`/`StartNetGame`). Each repair removes
  its allowlist entry — the allowlist doubles as the legacy-compat backlog.
- Adjacency flagged by recon (separate, ~3-line): `bbruntime_dll.cpp:59-66`
  `seTranslator` switch has no `break`s, so structured-exception diagnostics are
  mislabeled. Not part of this increment.
