# corpus_compile_allowlist.txt
#
# Files under samples/ tutorials/ games/ that do NOT compile today with
# `blitzcc -c +q`. The compile-sweep gate (scripts/sweep_corpus.sh) treats these
# as known failures so it can ratchet: any NEW compile failure (a file not listed
# here) fails CI. Remove an entry once its underlying cause is fixed.
#
# Paths are repo-relative with forward slashes. Inline `# ...` comments are
# ignored by the gate; they record the failure cause. Baseline: 32 files.
#
# The four failure classes below double as a legacy-compatibility backlog; each
# repair removes its line(s) from this list.
#
# Baseline reflects the Windows runtime's registered command set (the stable
# target). The sweep is currently gated in CI on the Windows job only; gating the
# macOS alpha job would need a baseline regenerated against its runtime metadata.

# that classic Blitz3D allowed as identifiers. The HIGH-priority contextual-keyword
# fix would re-enable these. (`object` is a legacy Blitz3D keyword, not a fork
# addition, but the program still uses it as an identifier.)
# NOTE: the `test`-collision files (fileio/global/mirror/deathisland) were removed
# once `Test` became a contextual keyword (PR: align/legacy-test-keyword-identifier),
# and `spindisc.bb` once `Release` became contextual (PR: align/legacy-release-keyword-identifier).
# `object` remains: it is a *base* Blitz3D keyword (Object.Type(handle)), not a fork
# addition, so it is a different problem class -- deferred for separate investigation.
